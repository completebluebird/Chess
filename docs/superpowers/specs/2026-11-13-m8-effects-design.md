# M8 이펙트와 카메라 연출 설계

작성일: 2026-11-13 · 상태: 초안 (사용자 승인 대기)
기반 문서: `docs/design/phase1.md`의 "뷰" 절, `docs/roadmap.md`의 M8, `docs/design/tuning.md`

## 의도

규칙은 이미 Core에서 끝나 있다. M8의 목표는 플레이어가 **지금 무슨 일이 일어났는지 화면만 보고 알 수 있게** 만드는 것이다. 공격 종류, 피격 원인, 각성 상태가 색과 모양과 움직임으로 구분되어야 한다. 아트는 M7 이후 교체하므로, 이번에는 캡슐·큐브·칸 색과 Unity 기본 파티클로 충분히 읽히게 한다.

## 목표

1. 일반 공격(Q/E)과 각성 공격이 모양으로 구분된다.
2. 각성 연출(타오르는 불기둥)과 화상 연출(발밑 불씨)이 서로 다른 모양과 방향이어서 헷갈리지 않는다.
3. 피격 종류 4가지(물기, 레이저, 화염, 운석)가 화면과 폰 움직임으로 구분된다.
4. 기획서 이펙트 표 10종과 카메라 요구(가림 반투명, 각성 줌인·줌아웃)를 모두 넣는다.

## 비목표

- 아트 교체와 모델링 (M9)
- 음원 제작과 믹싱 (M9). 이번에는 소리 호출 지점만 만든다.
- 2페이즈 연출, 잡몹 연출
- 규칙 변경. 공격 판정, 데미지, 쿨다운은 Core에서만 바꾼다.

## 안티 목표

- 연출 때문에 판정이 흐려지면 실패다. 예고 칸(빨강)과 판정이 어긋나면 안 된다.
- 화면 효과가 강해서 보스나 폰이 안 보이면 실패다. 특히 불 효과와 비네팅이 폰을 가리면 안 된다.

## 제약

- Core에는 `UnityEngine`을 쓰지 않는다. 연출은 `ChessBoss.Game`에만 둔다. (CLAUDE.md 규칙)
- 시간은 두 가지로 나눈다. 히트스톱·슬로모션은 `BattleTime`(게임 시간), 카메라 흔들림·화면 효과·UI는 unscaled time. (CLAUDE.md 규칙)
- 숫자는 `BattleTuning` 에셋에 둔다. 코드에 박지 않는다.
- 씬·프리팹 YAML을 손으로 고치지 않는다. 이펙트는 코드로 생성한다. (CLAUDE.md 규칙)
- 새 패키지를 추가하지 않는다. 무료 이펙트 팩은 쓰지 않는다 (라이선스 기록 부담, M9 전에 아트를 고정하지 않기 위해).

## 접근 방식

**A. 코드로 이펙트 생성 (추천, 채택)**
`Game/Effects/` 아래에 `ParticleSystem`을 코드로 만들고, 이벤트 한 줄로 재생한다. 모든 연출이 한곳에서 관리되고, PR마다 diff가 작다. 단점은 파티클 튜닝을 인스펙터에서 한눈에 보기 어렵다는 것이다.

**B. 프리팹으로 만들기**
Unity 에디터에서 프리팹을 하나씩 만든다. 눈으로 튜닝하기 쉽다. 하지만 `.meta`와 YAML 변경이 크고, 리뷰하기 어렵고, CLAUDE.md가 금지한 방식이다.

**C. 셰이더와 머티리얼로 화면 효과만 만들기**
비네팅과 화면 불은 전부 URP 포스트 프로세스나 풀스크린 셰이더로 만든다. 파티클보다 가볍지만, 셰이더 작업이 커져 M8의 범위를 넘는다. 화면 불 효과에만 부분적으로 쓴다.

채택: **A**를 기본으로 하고, 화면 가장자리 효과에만 **C**의 가벼운 버전(URP Volume의 Vignette 가중치 변경)을 쓴다. 이유는 CLAUDE.md의 "씬 YAML을 손으로 고치지 않는다" 규칙과 맞고, 리뷰 가능한 단위로 PR을 쪼갤 수 있기 때문이다.

## 연출 목록

### 공격

| 대상 | 트리거 | 연출 |
|---|---|---|
| 일반 공격 (Q/E) | `PawnController.Attack` 성공 | 검 슬래시: 보스 쪽으로 호를 그리는 얇은 흰 띠(0.15초). 적중 시 짧은 히트스톱 |
| 비숍 | 대각선 돌진 | 창이 찌르듯 대각선으로 빠르게 뻗고, 경로 끝에서 밝은 스파크 |
| 룩 W/S | 줄을 따라 관통 | 비숍과 같은 창 모션, 직선으로 뻗음 |
| 룩 A/D | 앞 고리 한 바퀴 | 앞 고리 칸을 순서대로 훑는 흰 호. 칸마다 짧은 스파크 |
| 나이트 | 착지 | 점프 호, 착지 시 땅 울림: 카메라 약한 흔들림 + 착지 칸 주변 먼지 링 |

### 각성

| 대상 | 트리거 | 연출 |
|---|---|---|
| 각성 시작 | 1/2/3 입력 | **흰·금빛 불기둥이 위로 솟음** (각성 전용 색과 방향). 함께 "투캉!" 소리 호출 |
| 각성 중 | 각성 대기 | 폰 주변 불기둥 유지, 캐릭터 발광 |
| 각성 종료 | 발동 또는 시간 초과 | 불기둥이 위로 흩어지며 사라짐 |
| 줌인·줌아웃 | 각성 시작·공격 가능 칸 표시 | 카메라 FOV/거리 보간 (unscaled time) |

### 화상 (구분을 위한 기준)

| 대상 | 트리거 | 연출 |
|---|---|---|
| 화상 중 | 화상 도트 | **발밑에서 꺼지는 주황 불씨**, 위로 조금 올라가다 사라짐. 각성 불기둥과 색·방향 모두 다름 |

### 피격

| 대상 | 트리거 | 연출 |
|---|---|---|
| 물기 | 물기 피격 | 와그작 소리 호출 + 화면이 붉게 번쩍였다가 천천히 복귀 (약 0.6초, unscaled). 폰이 휘청 (좌우 흔들림 후 감쇠) |
| 레이저 | 레이저 피격 | 화면 가장자리 불꽃 (화면 불 효과) + 폰 휘청 + 폰에 불꽃 파티클 붙음 |
| 화염 (브레스) | 브레스 피격 | 같음. 화면 불 효과가 더 강함 |
| 운석 | 운석 착탄 | 화면 흔들림 강함 + 폰 휘청 + 폰에 불꽃 파티클 |

화면 흔들림 강도 차등: 레이저 약함, 운석·물기 강함 (기획서 표). 브레스는 중간.

### 기존 연출 정리

| 이펙트 (기획서 표) | 상태 | 비고 |
|---|---|---|
| 화면 흔들림 | 신규 | 강도 3단계 |
| 파티클 | 신규 | 브레스·레이저·운석·물기 |
| 화면 불 효과 | 신규 | 화면 가장자리 |
| 화상 표시 | 신규 | 발밑 불씨 |
| 히트스톱 0.05초 | 있음 | `BossView.PlayHit`. 값만 확인 |
| 보스 피격 플래시 | 있음 | `BossView.PlayHit` |
| 스턴 슬로모션 | 있음 | `BossAttackView`. 변경 없음 |
| 게이지 가득 참 | 신규 | 폰 발광 |
| 각성 | 신규 | 위 각성 절 |
| 저체력 비네팅 | 신규 | 플레이어 체력 임계 이하에서 가장자리 붉게 |

카메라 요구:
- 벽과 보스가 카메라와 폰 사이를 가리면 반투명 처리. 가림 판정은 카메라에서 폰으로 쏘는 레이캐스트 (프로토타입은 단순 거리 기반으로 시작).
- 각성 줌인·줌아웃: 기존 `BossCameraRig`에 오프셋만 추가.

## 구조

- `Game/Effects/EffectHub.cs`: 이벤트를 받아 해당 연출을 재생하는 한 곳. 호출부는 `EffectHub.Play(EffectKind, Vector3)` 한 줄.
- `Game/Effects/ScreenEffects.cs`: 화면 흔들림, 붉은 번쩍임, 비네팅, 화면 불 효과. unscaled time 사용.
- `Game/Effects/PawnEffects.cs`: 폰에 붙는 불꽃, 발광, 휘청 애니메이션.
- `Game/Effects/SoundCues.cs`: 소리 호출 지점만. 이름(`awaken`, `slash`, `bite`…)을 문자열 상수로 두고, 실제 재생은 M9에서 채운다. 이번에는 로그 또는 빈 구현.
- 호출부: `PawnController`(공격·각성·착지), `BossView`(피격), `BossAttackView`(공격 종류별 적중·착탄).

## 튜닝 항목 (`BattleTuning`에 추가)

- 흔들림 강도 3단계와 지속시간
- 화면 붉은 번쩍임 지속시간 (기본 0.6초)
- 휘청 각도와 감쇠
- 각성 불기둥 높이·지속시간
- 화상 불씨 개수·속도
- 줌인 거리, 보간 시간
- 비네팅 임계 체력 비율

## 검증

Core 규칙은 바꾸지 않으므로 EditMode 테스트 대상은 거의 없다. 대신 다음을 확인한다.

- 자동: 연출 호출 목록(`EffectKind`)이 기획서 이펙트 표 10종을 모두 덮는지 테스트
- 자동: 화상 불씨와 각성 불기둥이 같은 `EffectKind`를 쓰지 않는지 테스트
- 수동: 각 항목을 Unity에서 보고 PR 설명에 체크리스트로 적는다

## 열린 항목 (구현 중 판단)

- 화면 불 효과를 URP Volume으로 할지 풀스크린 셰이더로 할지: 구현 PR에서 Volume 쪽을 먼저 시도한다.
- 카메라 가림 판정 방식: 단순 거리로 시작하고, 부족하면 레이캐스트로 바꾼다.
- 로드맵의 "이펙트 11종"과 기획서 표 10종 차이: 기획서를 따르고, 빠진 한 종이 있으면 사용자에게 묻는다.

## PR 쪼개기 (제안)

1. 연출 기반: `EffectHub`, `SoundCues` 자리, 튜닝 항목
2. 타격감: 검 슬래시, 창 돌진, 착지 울림, 히트스톱 확인
3. 각성: 불기둥, 발광, 줌인·줌아웃
4. 피격: 화면 흔들림, 붉은 번쩍임, 폰 휘청, 화면 불 효과, 폰 불꽃
5. 화상 불씨와 비네팅, 카메라 가림 반투명
